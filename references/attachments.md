# 笔记、转发与本地媒体

先从搜索结果确定账号、聊天和消息 ID，再读取该账号的工作副本。不跨账号复用消息 ID。

## 首选后端能力

优先用已有 MCP 或 CLI 的笔记/媒体提取能力。确认其输出是否区分原件、缩略图、OCR、转写和未落地状态。后端没有提供某种能力时，明确缺口；不能假装已读取附件正文。

只有确需实现适配器时才检查数据库结构，且只检查工作副本。不同版本的微信数据库格式可能不同；下面内容是格式识别线索，必须先核对实际结构：

- 部分版本将消息存在 `Msg_<聊天标识的摘要>` 表中，正文可能使用 zstd 压缩。
- 部分版本需要取 `local_type` 的低 32 位才是消息类型。
- 某些笔记卡片的正文位于 `recorditem` 的 XML CDATA 中；普通索引可能只收录标题。
- 转发内容可能多层嵌套。限制输入大小和递归深度；仅提取允许的文本字段，不输出原始 XML。

## 凭据过滤

XML 属性、嵌套正文和 URL 都可能包含 `aeskey`、`cdn_datakey`、`encfilekey`、签名或令牌。过滤字段还不够，也要检查字段值中的嵌套内容和链接。不要把原始解析异常或 XML 作为诊断材料直接交付。

## 本地素材核对

- 只在已选账号的缓存范围内定位素材，拒绝符号链接指向其他账号或目录。
- 依后端提供的消息关联、大小和摘要校验对应文件，不能仅凭文件名、相邻位置或修改时间认领。
- 原图与缩略图分别标注；正文内的媒体数量可能同时包含图片和视频。
- 未落地的素材不自动访问 CDN，不触发客户端下载。
- 原文、照片和视频按已核对的关联关系展示；关键数字需核对原图或上下文。OCR 和转写须说明是机器结果。
- 用户需要导出时，写入本任务指定的私有目录，并核对复制后文件的完整性。
